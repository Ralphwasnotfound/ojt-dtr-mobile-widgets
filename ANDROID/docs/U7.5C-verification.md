## Companion behavior

The existing centralized home/About navigation remains, with home content
selected exclusively by current coordinator AccountState. Approved student/admin
content has no independently navigable route and accepts no role/status route
arguments. About is public information only. Every account transition, including
logout, withdrawal or refresh, reselects the current home content.

RestoringSession and LoadingProfile show progress; SignedOut offers Google;
Authenticating offers cancellation. Retryable failures offer Retry and logout;
unsupported/malformed states remain closed. Missing client configuration disables
sign-in. Existing security failures use generic user-facing messages.

Approved students see BSIT-TCC / OJT Monitoring & DTR identity, optional trusted
profile name/student ID, approved status, and Today’s DTR explicitly marked
not yet connected. No attendance values or actions are invented. Identity is
read from the same own-row query (`id,role,status,full_name,student_id`), after
current-session/user validation; it is display-only, never authorization input,
never taken from Google metadata, and not persisted. Missing labels are presented
as unavailable. Identity is cleared on refresh, failed access and logout.

Approved admins see minimal approved status, an explanation that administration
belongs on the web, Open Full DTR System and logout. No dashboard or mutations.
Pending accounts receive an approval explanation, safe explicit status refresh,
logout and the full-system browser link. Rejected accounts receive a clear
access-unavailable explanation and logout; no native self-approval, re-registration
or registration link is offered.

RegistrationRequired remains possible only after a successful empty own-profile
query for a verified Google identity. Its action opens the existing `/signup` web
route. The browser must use its own sign-in, preferably the same Google account;
Android does not transfer its native session. The Vue router enforces browser
access. Opening, returning from, cancelling or completing a browser page causes
no automatic native account change. Refresh account status explicitly rereads
the server and transitions only according to fresh verified profile results.

`WebDestinations` owns one fixed production HTTPS origin:
`https://bsit-tcc-ojt-dtr.vercel.app`. Full-system handoff uses `/`; registration
uses `/signup`. Destination policy rechecks live coordinator state at click time.
No arbitrary URL, tokens, identity parameters, query or fragment are appended.
MainActivity opens ACTION_VIEW/CATEGORY_BROWSABLE with no session extras; it shows
a generic notice if no browser handler exists. No WebView, clipboard transfer,
browser storage transfer or second backend was introduced.

Explicit recheck shares the existing retry path: advance epoch, cancel old work,
withdraw approval/identity, serialize SDK work, verify session/user, reread the
profile and recheck current client/session/user/epoch before publishing. Signed-out
and transitional states cannot initiate profile refresh. Logout retains immediate
authority withdrawal, fenced encrypted cleanup, bounded native revocation and
fresh client/lease creation. All U7.5B/B.1 regressions remain intact.

## Future widget boundary recommendation

- Authentication infrastructure exclusively owns SDK clients, tokens, encrypted
  session/PKCE storage, refresh, logout and authorization epochs/leases.
- A future account/DTR repository should access this infrastructure internally,
  issue only authorized own-user reads, and return minimal immutable derived
  account/today-DTR results. Raw UserSession, tokens and SDK clients must not
  cross the repository boundary. No DTR repository or endpoint is invented here.
- Companion UI observes current account state and optional display-only identity;
  it calls explicit coordinator actions. It cannot authorize itself from navigation
  or presentation values. The current identity flow is not a widget authorization
  cache and is not an independently trusted account state.
- A future widget adapter should receive only minimal derived display state such
  as unavailable/loading/approved/pending and actual server-derived DTR state plus
  freshness metadata. It should default to closed/unavailable after process start,
  clear snapshots on logout/session invalidation, and revalidate before any future
  action. Cached widget display must never authorize a write. Avoid student PII
  unless explicitly necessary; never store raw tokens in widget preferences.
- Glance, a widget provider, widget preferences, workers, Time In/Time Out,
  notifications and background attendance tracking remain unimplemented.
