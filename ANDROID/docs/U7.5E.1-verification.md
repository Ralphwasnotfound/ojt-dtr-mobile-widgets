# U7.5E.1 — Read-only home-screen widget foundation

Baseline: `7f3d7b1f9a8e7272e418afaf8ddf97559de13c99`, main, expected mobile origin;
clean pre-flight. Android changes only. No dependency versions changed.

## Architecture and authority

`DtrWidgetReceiver` exposes one resizable home-screen provider. `DtrWidget` uses
Glance 1.1.1 and crimson/gold BSIT TCC branding. Root tapping uses an explicit
MainActivity intent, without external destinations, credentials or account extras.
The provider has updatePeriodMillis=0 and no application worker/service/polling loop.
Glance internally uses its own rendering worker; it performs no backend operation.

DtrApplication authentication is now lazy: a widget-only process does not initialize
AuthCoordinator, restore a native session or start backend HTTP. The normal Activity
and OAuth callback entry points still initialize the existing coordinator. Widget
rendering may inspect only an already initialized coordinator.

The coordinator derives WidgetPresentation after checking its current client, session,
user, authorization epoch, approved-student state and attendance binding. Presentation
contains only message, completed/remaining display values, IN/OUT label and the display
confirmation time. It contains no account identifier, tokens, SDK objects, PKCE, proof,
location, selfie, raw responses or individual attendance rows. Auth/attendance changes
update one read-only in-memory presentation flow and request updates for all widgets.
Logout, replacement, rejected/pending/admin states and SDK invalidation withdraw values.
The widget cannot request attendance refresh, mutations, or independent authentication.

## Freshness, process death and host limitations

No durable attendance snapshot is implemented. Glance stateDefinition is null; no
attendance is written to preferences, files or a database. On process recreation the
presentation starts as unavailable and widget rendering does not initialize auth.
No in-memory account snapshot is recovered across process death. The existing encrypted
native authentication storage remains independent and is accessed only by the companion.

ALL widget attendance values are labelled Stale — open app to verify, even when their
source was Fresh. Android does not guarantee a 120-second background redraw, so the
widget never promises Fresh authority. The existing companion monotonic expiry,
foreground profile revalidation and Manila-day policy remain unchanged. Durations and
status derive from the validated server summary, not local next_action calculations.

Launchers receive RemoteViews and may retain previously rendered minimal aggregate
text after process death, host update failure or delayed redraw. Clearing app memory
cannot recall already delivered host views synchronously. App logout/withdrawal queues
neutral rendering; actual launcher delivery is asynchronous. Opening the companion is
required to establish current authority. This widget is not an authorization surface.
Do not use this foundation for attendance actions or claim instant launcher revocation.
No private identity/attendance-row/proof details are published to the host. A durable,
account-bound encrypted widget cache is deliberately deferred rather than invented.

## U7.5E.1.1 — invalidation correction

The adversarial review found a Medium defect: Glance 1.1.1 updateAll iterates IDs
sequentially, while the application caught exceptions around the whole batch. A failed
first instance could prevent all remaining instances from receiving neutral updates.
There was no recovery after a final logout notification. The Low publication-race
coverage gap is also addressed through the production publication coordinator.

DtrApplication now uses WidgetPublication and GlanceAppWidgetManager.getGlanceIds.
Each ID has an independent update attempt. Ordinary Exceptions are isolated per ID;
CancellationException propagates and fatal JVM errors are not caught. A mutex serializes
publication; collectLatest cancels superseded work. The upstream onEach withdraws the
in-memory presentation before cancellation waits for older, non-cooperative rendering.
Updates receive IDs only and the renderer consumes current presentation, never a saved
authorized payload. Current coordinator session/client/user/epoch checks are preserved.

Failed neutral updates get at most two recovery passes, after 250ms and 1000ms, in the
same cancellable coroutine. Each pass re-enumerates live IDs, drops removed IDs and
rechecks current authority before attempts. Enumeration failures have the same bounded
recovery. A new approved presentation stops the old neutral retry pass. There is no
persistent job, uncontrolled polling or extra backend read. Exhaustion leaves neutral
in-memory state; process death or host failures can still prevent launcher delivery.
Already-submitted host rendering may finish late; subsequent neutral attempts repair it
when delivery succeeds. Immediate host revocation is not guaranteed.

Eleven new JVM tests exercise the production WidgetPublication: independent failures,
transient recovery, exhaustion, removal, cancellation, fatal errors, enumeration failure,
new approval, serialized concurrent refresh and non-cooperative delayed publication for
logout, revocation, replacement and SDK invalidation. Four additional Samsung tests use
the real AuthCoordinator and its synthetic SDK backend with the same observe pipeline
as DtrApplication. Barriers hold an old approved update across each transition; neutral
presentation must appear before release, and both simulated hosts must ultimately be
neutral despite a first-instance failure. They assert publication adds no attendance RPC.
U7.5E.1.1 verification: 71 debug and 71 release unit tests passed, zero failures,
errors or skips. Debug/release builds and instrumentation APK passed. Lint passed
with zero errors and the same 20 warnings. Samsung SM-A065F / API 36: all 45
instrumentation tests passed in one run (44.559s), including all four new publication
barrier tests. Only project APKs were installed with data-preserving replacement;
no application data was cleared. No emulator or live backend operations were used.
Whitespace and changed-file checks passed; no files staged, committed or pushed.
Gradle daemons were stopped after this verification.

The injected host boundary is not a real launcher RemoteViews delivery test. Unsolicited
SDK replacement is rejected; these tests do not claim successful replacement OAuth.

## Restrictions and remaining work

No production credentials, live attendance mutations, proof permissions, hosted changes,
Vue/iOS edits, emulator, commit or push. Native backend configuration is blank for test
builds; synthetic MockEngine clients and isolated Keystore directories are used.
Existing PKCE wall-clock age, custom URI ownership and previously accepted test-barrier
limitations remain deferred. Live RPC deployment, approved production widget display,
launcher process-death retention and background scheduling require future authorized
live/device acceptance. Exact 120-second host redraw and instantaneous clearing are
not promised.
