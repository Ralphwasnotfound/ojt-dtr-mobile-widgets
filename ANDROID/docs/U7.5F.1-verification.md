# U7.5F.1 — Device-only native camera and GPS foundation

Baseline: `513db527a8d908192225e1247ce4f04465b4e412`, main equals origin/main,
clean pre-flight; expected mobile remote. Android-only implementation; no commit/push.

## Architecture

Approved companion navigation offers a device-only selfie/location screen. CameraX
camera-camera2, camera-lifecycle and camera-view are newly pinned to 1.5.3; no existing
version was deliberately upgraded. ExifInterface 1.4.2 (already brought by CameraX)
is explicitly declared for maintained JPEG orientation handling. Version selection and PreviewView binding follow
[CameraX releases](https://developer.android.com/jetpack/androidx/releases/camera) and
[preview documentation](https://developer.android.com/media/camera/camerax/preview).
Location uses platform LocationManager, avoiding a second SDK or authentication pipeline.

ProofSession is a screen-owned Main-dispatcher controller with injected camera/location,
current-authorization, revalidation and monotonic-time interfaces. It exposes only capture
presence, busy/error/confirmation state, accuracy and permission precision to normal UI.
Raw coordinates stay in an ephemeral private Fix; images are never placed in widget state.

## Camera and temporary data

CameraX binds front-facing Preview and ImageCapture to the screen lifecycle. A late provider
initialization checks screen ownership before binding. Owned use cases alone are unbound;
recomposition does not create duplicate sessions. Capture is coalesced and bounded by a
20-second timeout. Permission requests use Activity Result APIs; denial offers retry,
permanent denial explains app Settings. Hardware absence/disconnection/capture failure
produce fixed error classifications rather than raw SDK errors or image logs.

JPEGs are confined to cache/native-proof/<random screen UUID>/<random UUID>.jpg, never
public media, external storage or an intent. Captured previews are downsampled and account
for EXIF orientation. Retake deletes the image and clears the location. Confirm deletes
both proof states; it records no attendance. Leaving, lifecycle pause, known authorization
withdrawal and logout stop hardware, cancel requests and delete the screen directory.
Late capture callbacks delete abandoned output; no old result may populate the controller.
Application startup removes orphan proof cache after process death without initializing
authentication. If startup cleanup fails, proof entry is blocked. Filesystem deletion
failure is surfaced; absolute deletion cannot be guaranteed under storage failure.
Cache is excluded from Android backup. No image persists intentionally beyond the screen.

FLAG_SECURE protects the proof screen. There are no camera/GPS values in application logs,
analytics, preferences, widget state or external intents. No Supabase Storage or proof/
attendance mutation RPC was added.

## Foreground location

Only CAMERA, ACCESS_COARSE_LOCATION and ACCESS_FINE_LOCATION are added; background
location is absent. Hardware features are optional. A user-triggered request selects
available GPS/network providers consistent with foreground permission; approximate access
is supported through network location. It stops on the first result/error/cancellation or
20-second timeout. No continuous or background tracking service exists.

Location fix validation rejects non-finite/out-of-range coordinates, absent/non-finite/
non-positive accuracy and monotonic ages outside 0–30 seconds. No unchecked last-known
location is used. A recent provider-delivered fix can still be cached by Android; its age
is checked. Confirmation checks age again after authorization revalidation. UI shows only
acquired/unavailable, accuracy in meters and approximate/precise permission, never raw
coordinates. Fine permission is not a promise of GPS accuracy. Disabled/unavailable
providers, permission denial, invalid/stale fixes and timeout are explicit errors.

## Authorization

A proof ticket is the existing private attendance authorization binding, fenced by SDK
client/session/user identity, authorization generation, approved student status and expiry.
Pending, rejected, admin and signed-out accounts receive no ticket. No independent native
or widget authentication exists. Synchronous coordinator cancellation registrations stop
proof controllers when attendance authority is withdrawn/replaced; stale callbacks also
check screen revision and current ticket. Confirmation retrieves the current user and
own approved student profile with the existing SDK under a deadline, checking ownership
before/after I/O. A known attendance AccessDenied also invalidates proof tickets and
notifies active screens even while the cached account state remains approved. The proof
listener is a cancellable state-flow subscription, not polling. Failure withdraws authority; no proof or attendance endpoint is called.

Pause is intentionally conservative: the draft is discarded and the screen returns to
the companion. Permission dialogs or Settings handoff that pause the Activity can require
reopening the screen after granting permission. This avoids keeping a draft across
foreground account revalidation or another authorization generation.
